No frozen LLM has been cleared beyond an owner's README statement.

## 1. Method

- Sources were chosen from the plan's D1, D2, D3 and Tier 2 descriptions (the plan requires a frozen open-weights LLM that fits an L4 in BF16, QA datasets with verified licences, a labelled operational sensor dataset, and a graph domain). The list is not exhaustive and it was written from prior knowledge of what exists; a source missing from the register was not judged.
- For each source `scripts/licence_survey.py snapshot` fetched the owner's `LICENSE` file and README from the default branch, and recorded status, size, SHA-256 and licence-related lines. The hash pins the content that was read.
- The rubric is in [`README.md`](README.md): **code licence is not data licence**, and a verdict needs a permissive licence for the asset itself.
- Usability probes (`scripts/licence_survey.py probe`) downloaded small samples of the data that GitHub hosts and recorded structure only.

### 2.1 D2: LLM context

- **MuSiQue** is the only `adopt`: the README says it is distributed under CC BY 4.0 and the repository `LICENSE` is CC BY 4.0. Gaps: the data files are hosted off GitHub and were not fetched, and how its upstream source datasets are licensed is not reconciled by the owner statement. Whether its paragraph-set contexts suit an exhaustive keep/drop oracle is a design question, not something this survey measured.
- **QuALITY** is the only D2 set whose data could be downloaded and inspected (`probes.jsonl`, probe `quality`; the zip is 18,023,502 bytes, SHA-256 `58552970…437341`). Its `htmlstripped` files hold 381 articles, 762 question sets and 6,737 questions across train, dev and test. Every article carries a `license` field: **285 articles are under the Project Gutenberg licence, 66 cite the OANC licence URL and 30 are CC BY 4.0** (the counts per split are in the probe). None is non-commercial or no-derivatives. But the repository has no licence file, and no read source states a licence for the questions, options and labels. It is `adopt_with_conditions` until the authors or the Hugging Face card settle the annotations.
- **HotpotQA** states CC BY-SA 4.0 for the data and Apache 2.0 for the code (README section License): share-alike is the condition. **TriviaQA** states Apache 2.0 for code and data, but its evidence documents are web text with terms that were not read. **NarrativeQA**, **LongBench**, **RULER**, **2WikiMultihopQA** and **Qasper** are `unverified`: only code licences were read.
- **Frozen models.** **Qwen3** and **Granite 3.0** each say in their own README that their open-weight models are Apache 2.0; **for both, the checkpoint's own licence file (on Hugging Face) was not read**, so both are `adopt_with_conditions`. **Llama 3.1** was read in full: the community licence requires "Built with Llama" attribution, incorporates an acceptable-use policy, requires a licence request above 700 million monthly active users and terminates if you sue Meta alleging that the Llama Materials or their outputs infringe your rights. It is not permissive by this project's definition. **Mistral**'s README lists non-commercial licences (MNPL, MRL) for some checkpoints, so each checkpoint needs its own read. **OLMo**, **Gemma**, **Phi** and **SmolLM** are `unverified` (repository code licences only). Whether any of these fits an L4 in BF16 was not checked.

### 2.2 D1: sensor streams

| Source | Licence as read | Probe result (sample, structure only) |
|---|---|---|
| SMD (`NetManAIOps/OmniAnomaly`) | MIT (repository `LICENSE`) | `machine-1-1` training file: 38 numeric columns, no header, 383 rows in the first 128 KiB; a separate label file has 1 column |

| SKAB | GPL-3.0 (repository `LICENSE`) | `valve1/0.csv`: `datetime`, 8 sensor channels, `anomaly` and `changepoint` label columns, 681 rows in the first 64 KiB |

- **SMD is the best D1 candidate on evidence read:** permissive, 38 channels, separate labels. Gap: the README does not say where the server metrics come from or that the licence covers the data.
- **NAB is permissive but univariate** in the file probed, so it is a weak fit for a channel-by-time hierarchy.
- **ETT** is no-derivatives: use as is and do not share adapted copies (data stays out of git anyway). **SKAB** is copyleft with unclear scope over data and derived artefacts.
- **SMAP/MSL** (via telemanom) is `unverified`: the code is Apache 2.0 but the data comes from a Kaggle mirror whose terms were unreachable. The `laiguokun` multivariate series (electricity, traffic, solar, exchange rate) have **no licence file and no licence statement**, so they are `avoid` until the owner clarifies.
- Not reachable, hence `unread`: UCI electricity load, the Monash forecasting archive and NASA C-MAPSS.

### 2.3 D3: graph domain (open question 2)

- **Code-repository context** has no `adopt`. **CrossCodeEval** says Apache 2.0 for a repository that holds its data and inference code, but the data is third-party source code whose upstream licences were not read. **CodeSearchNet** is MIT for code and documentation and states that the licences of the source code used as data are recorded per file in `_licenses.pkl` inside the (large) data download; those files were not fetched, so a per-file licence filter would be needed. **SWE-bench**, **RepoBench**, **CodeXGLUE** (data under C-UDA, text unread) and **RepoQA** are `unverified`.
- **Query planning:** **JOB** has no licence file and defers to the IMDB terms (unread); **DSB** is MIT code but derived from TPC-DS, whose terms are unread; **STATS-CEB** has no licence file and is `avoid`.
- **The evidence read does not settle which graph domain to choose.** The code-repository route needs either a per-file licence filter over a public corpus or a corpus assembled from repositories whose licences we read; the query-planning route depends on TPC terms and on synthetic data generated by a licence-unread generator. Both need reads from hosts that were blocked.

### 2.4 Tier 2

- **Cloud scheduling:** the Google cluster-usage README states the traces are CC-BY (4.0) (`adopt`; the trace files were not fetched). The Azure public dataset repository carries a CC BY 4.0 `LICENSE`, but its README does not say that it covers the trace files, so it is `unverified`. The Alibaba traces have no licence file, only an encouragement to use them "for study or research purposes", so they are `avoid`.
- **Ranking:** **BEIR** disclaims any claim that you may use its datasets and defers to each dataset's licence; **MS MARCO** requires agreeing to terms on a host that could not be read. Both are `unverified`. **CIC-IDS2017** (security) was not read.

## 3. What this does and does not support

**Supports:**

- The specific licence strings and owner statements quoted above, as read on 2026-09-29 (each is pinned by URL and SHA-256 in `evidence.jsonl`).
- QuALITY's per-article licence counts and sizes, and the column structure of the SMD, NAB, ETT and SKAB samples.
- That the verdicts follow the rubric (`tests/test_licences.py`).

**Does not support:**

- Any statement about a licence that is `unread` or `unverified`. In particular no model checkpoint card, no Hugging Face dataset card and no non-GitHub dataset page was read.
- Legal advice. An owner statement is what the owner says, not a legal determination; upstream third-party content may carry its own terms.
- Scientific fit. A probe shows that a file loads and how many columns it has, not that it makes a good benchmark or that a hierarchy can be built.
- Completeness of the source list.

## 4. Recommendation

1. **D1 first candidate: SMD**, with NAB as a univariate control and ETT only under its no-derivatives condition. Before D1-0 adapters are written, read SMD's data provenance (ask the owners or read the paper).
2. **D2:** plan on **MuSiQue** as the first QA set and **QuALITY** as a second, and choose a **Qwen3** checkpoint (owner-stated Apache 2.0) after reading that checkpoint's own licence file. Do not use Llama or any non-Apache checkpoint unless Roman approves the conditions.
3. **D3:** do not start. Decide between code-repository context and query planning after the blocked reads (SWE-bench, The Stack v2, TPC terms), and only then.
4. **Tier 2:** Google cluster traces are the only permissive candidate so far; nothing else is ready.
5. **Unblock the reads** (§5). This is the gate for D2-0, D1-0 and D3-0: the plan says nothing is built for D1–D3 before this survey reports, and it has reported only in part.
6. **D4-2 does not depend on this survey** and can run in parallel (CPU).

## 5. Hosts the sandbox could not reach

`curl` returned status 000 (no answer) for these hosts on 2026-09-29: `huggingface.co`, `archive.ics.uci.edu`, `zenodo.org`, `physionet.org`, `kaggle.com`, `figshare.com`, `data.mendeley.com`, `data.nasa.gov`, `ti.arc.nasa.gov`, `www.tpc.org`, `creativecommons.org`, `spdx.org`, `opensource.org`, `choosealicense.com`, `arxiv.org`, `openreview.net` and `paperswithcode.com`. A WebFetch of a Hugging Face model card was refused with "blocked by the network egress proxy". `github.com` pages return 400 or 403, and `api.github.com/repos/…` returns 403 for repositories not attached to the session, so only raw file contents were readable.

Either widen the environment's network access to at least `huggingface.co` and its CDN, `archive.ics.uci.edu`, `zenodo.org`, `physionet.org`, `www.tpc.org` and `creativecommons.org` (Environment settings, Network access), or run the two commands in the README on Colab, where these hosts are reachable, and commit the updated `evidence.jsonl` and `probes.jsonl`.
